# E3 一页说明：规格先行与 AI 结对修复

题目：E3-02 购物车合并的修改时间（个人选题，非教师示例）。

## 规格小表

| 输入 | 期望结果 |
|---|---|
| 已存在条目（同会员、同商品、同 SKU、未删除） | 数量累加（旧 + 新）；被保存条目的 `modifyDate` 刷新为当前时间；走 update 分支 |
| 新商品（无已存在条目） | 走 insert 分支；`createDate` 设为当前时间；不触达 update |

不可变约束（不得修改）：数量累加公式、插入分支逻辑、公开接口 `add` 签名、表结构与生成代码。

## 失败断言

红灯来自业务断言，非编译/环境错误：`CartMergeModifyDateTest.mergeRefreshesSavedModifyDate` 给已存在条目一个旧时间 `1000`，断言保存后的 `modifyDate` 落在调用时间窗内。修复前失败为

```
saved modifyDate=1000 must not be before call start ==> expected: <false> but was: <true>
```

`Tests run: 2, Failures: 1, Errors: 0, Skipped: 0`。

## 修复理由

`OmsCartItemServiceImpl.add` 第 50 行把 `modifyDate` 设到传入的 `cartItem`（不被持久化），而第 52 行 `updateByPrimaryKey(existCartItem)` 保存的是 `existCartItem`，对象不一致。修复只改一行，让修改时间写到被保存的对象上；不动数量公式、插入分支和公开接口。

## 当前结果

`SDC/compare.sh E3-20244350127`：改前 `fail`（预期 fail）、改后 `pass`，结论「符合」（`evidence/compare.txt`）；只提交测试时改后仍 `fail`、结论「不符合」，证明红灯先行（`evidence/compare-red.txt`）。目标方法 `add` 行覆盖 12/12、分支 2/2（`evidence/coverage.txt`）。
