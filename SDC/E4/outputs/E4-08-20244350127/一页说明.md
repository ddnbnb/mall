# E4-08 管理员服务与缓存服务的循环依赖（替换依赖改造）

## 原来的问题是什么？

`UmsAdminServiceImpl` 与 `UmsAdminCacheServiceImpl` 之间存在一条服务层回边（循环依赖）：

```text
改前：UmsAdminServiceImpl --(SpringUtil.getBean 服务定位)--> UmsAdminCacheServiceImpl
      UmsAdminCacheServiceImpl --(@Autowired 字段注入 adminService)--> UmsAdminService --> UmsAdminMapper
```

- 管理员服务没有注入缓存服务，而是用 `SpringUtil.getBean(UmsAdminCacheService.class)` 在运行时“定位”它，掩盖了回边。
- 缓存服务用 `@Autowired private UmsAdminService adminService`（字段注入）反向依赖管理员服务，`delAdmin(id)` 靠 `adminService.getItem(id)` 回查用户名。
- 原有测试接缝：要换掉它只能 mock 静态 `SpringUtil.applicationContext` 再反射写私有字段，依赖被藏在全局上下文里。

## 依据是什么？

- 原则：T4 依赖注入——依赖倒置是原则、控制反转是思想、注入是手段；依赖应显式从构造参数进入，而不是靠全局上下文定位。
- 关键文件与当前行号：
  - `UmsAdminServiceImpl.java:46`（`cacheService` 字段）、`:61-62`（构造器）
  - `UmsAdminCacheServiceImpl.java:27`（`adminMapper` 字段）、`:44-45`（`delAdmin` 直连 Mapper）
  - `UmsAdminService.java` 原 `:88-91`（`getCacheService()` 接口方法）

## 我做了什么？

改后：`UmsAdminServiceImpl --> UmsAdminCacheService`（构造注入）；`UmsAdminCacheServiceImpl --> UmsAdminMapper`（直连持久层），无服务层回边。

| 文件 | 位置 | 改动 |
|---|---|---|
| `UmsAdminCacheServiceImpl.java` | `:27`、`:44-45` | `adminService` → `adminMapper`；`delAdmin` 改为 `adminMapper.selectByPrimaryKey(id)` |
| `UmsAdminServiceImpl.java` | `:46`、`:61-62` | 新增 `private final UmsAdminCacheService cacheService` + 构造器注入；删 `SpringUtil` import 与 `getCacheService()`；内部 12 处改为 `cacheService` |
| `UmsAdminService.java` | 原 `:88-91` | 删除 `getCacheService()` 接口方法 |

- 同步调用方：`getCacheService()` 无外部调用者，仅 `UmsAdminServiceImpl` 内部 12 处；直接 `new` 只在测试中，生产无 `new` 调用点。`UmsResourceServiceImpl:25`、`UmsRoleServiceImpl:33` 仍字段注入 `UmsAdminCacheService`，与本次循环无关，不改。
- 必须保持的可观察行为：缓存 key 格式（`database:key:…`）、失效时机与公开 HTTP 路径不变；删除先落库再回查用户名；记录不存在时不删管理员缓存、仍删资源缓存。
- 参考 `origin/exp/e4-08`（教师参考实现），本分支为本人实现。

## 为什么这样做？

- 遵循依赖注入：依赖显式传入后，测试不必反射改静态上下文、不必启动 Spring；缓存服务要的只是“按 ID 取用户名”，`UmsAdminMapper` 是该数据的最小正确边界，与 portal 的 `UmsMemberCacheServiceImpl` 一致。
- 一项代价：缓存服务越过业务层直连持久层 Mapper。
- 未采用“把用户名传入 `delAdmin(id, username)`”：删除/改密/更新路径并非都天然持有可信用户名，接口更复杂、易在改名场景失效错 key。
- 循环依赖不能机械替换注解：两边都改构造注入会形成构造循环而无法装配；须先消除真实回边，再替换服务定位器。

| 比较项 | 改前（字段注入 + 服务定位器） | 改后（构造注入 + 直连 Mapper） |
|---|---|---|
| 换掉依赖 | mock `ApplicationContext` + `setField(SpringUtil, "applicationContext", …)`；`setField("adminService", …)` | `new UmsAdminServiceImpl(cacheService)`；`setField("adminMapper", …)` |
| 依赖能否 final | 不能 | 能（`cacheService` 为 final） |
| 构造签名 | 无参构造 + 静态上下文 | 带 `UmsAdminCacheService` 参数的构造器 |
| 调用方代价 | 运行时隐藏依赖 | 内部 12 处改字段访问；签名 +1 参数 |
