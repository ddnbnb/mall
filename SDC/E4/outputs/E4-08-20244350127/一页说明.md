# E4-08 管理员服务与缓存服务的循环依赖（替换依赖改造）

## 一、原来的问题是什么（依赖从哪里进入）

`UmsAdminServiceImpl` 与 `UmsAdminCacheServiceImpl` 之间存在一条服务层回边（循环依赖）：

```text
改前：
UmsAdminServiceImpl --(SpringUtil.getBean 服务定位)--> UmsAdminCacheServiceImpl
UmsAdminCacheServiceImpl --(@Autowired 字段注入 adminService)--> UmsAdminService --> UmsAdminMapper
```

- 管理员服务没有注入缓存服务，而是通过 `SpringUtil.getBean(UmsAdminCacheService.class)` 在运行时“定位”它（服务定位器，掩盖了回边）。
- 缓存服务用 `@Autowired private UmsAdminService adminService`（字段注入）反向依赖管理员服务，`delAdmin(id)` 通过 `adminService.getItem(id)` 回查用户名。

```text
改后：
UmsAdminServiceImpl --> UmsAdminCacheService        （构造注入）
UmsAdminCacheServiceImpl --> UmsAdminMapper          （直连持久层）
UmsAdminServiceImpl --> UmsAdminMapper
```

没有服务层回边，也不再通过全局上下文定位缓存服务。

## 二、改动位置与调用方

| 文件 | 位置 | 改动 |
|---|---|---|
| `UmsAdminCacheServiceImpl.java` | `:27` 字段、`:44-45` `delAdmin` | 注入 `UmsAdminMapper` 替代 `UmsAdminService`，`delAdmin` 改为 `adminMapper.selectByPrimaryKey(id)` 回查用户名 |
| `UmsAdminServiceImpl.java` | `:46` 字段、`:61-62` 构造器 | 新增 `private final UmsAdminCacheService cacheService` + 构造器注入；删除 `SpringUtil` import 与 `getCacheService()` 方法 |
| `UmsAdminService.java` | 原 `:88-91` | 删除 `getCacheService()` 接口方法 |

- 同步调用方：`getCacheService()` 无外部调用者，仅 `UmsAdminServiceImpl` 内部 12 处，已全部改为 `cacheService`。
- 不受影响：`UmsResourceServiceImpl:25`、`UmsRoleServiceImpl:33` 仍字段注入 `UmsAdminCacheService`，与本次循环无关，不改。

**必须保持的可观察行为**：缓存 key 格式（`database:key:…`）、失效时机与公开 HTTP 路径不变；删除先落库再回查用户名；记录不存在时不删管理员缓存、仍删资源缓存。

## 三、依据与代价（改前/改后构造方式对比）

| 比较项 | 改前（字段注入 + 服务定位器） | 改后（构造注入 + 直连 Mapper） |
|---|---|---|
| 换掉依赖 | 测试 mock `ApplicationContext` 并 `ReflectionTestUtils.setField(SpringUtil.class, "applicationContext", …)`；缓存服务 `setField("adminService", …)` | `new UmsAdminServiceImpl(cacheService)` 直接传替身；缓存服务 `setField("adminMapper", …)` |
| 依赖能否 final | 不能（字段非 final） | 能（`cacheService` 为 final） |
| 构造签名 | 无参构造 + 静态上下文 | 带 `UmsAdminCacheService` 参数的构造器 |
| 调用方代价 | 运行时隐藏依赖 | 内部 12 处改为字段访问；签名加 1 个参数 |

- 方案取舍：缓存服务需要的是“按 ID 取用户名”，直接依赖 `UmsAdminMapper` 是该数据的最小正确访问边界，与 portal 的 `UmsMemberCacheServiceImpl` 一致；代价是缓存服务越过业务层直连持久层。
- 未采用“把用户名传入 `delAdmin(id, username)`”：删除/改密/更新路径并非都天然持有可信用户名，接口更复杂，也易在改名场景失效错 key。
- 循环依赖不能机械替换注解：若把两边都改成构造注入，会形成构造循环而无法装配；先消除真实回边（缓存服务直连 Mapper），再替换服务定位器。
